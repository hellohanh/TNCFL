Data

public/site_data.json is fetched once (useRecordBookData) and passed down via the outlet context. It is generated by the HMOTW engine pipeline — never hand-edited. Only this copy is live; the copies under docs/ and tncfl/ are frozen old-hub snapshots.

Mobile system (≤820px)

  • Breakpoint: 820px everywhere — CSS media queries and lib/useIsPhone.ts. Reference device: Galaxy S25 (360×780, 3×). Desktop must not change when doing phone work.
  • MobileTabDrawer: left-edge yellow handle, tap/swipe to open, tapped tab highlights instantly then navigates.
  • RotateOnPhone: wraps a panel; on an upright phone it lays the panel out at landscape length and draws it rotated −90°. Equal-height fill: scale so the turned height = phone content width (every flipped panel shares it) and the length fills the visible screen below the header; tables/pyramids that need more length run longer. Measures lazily (IntersectionObserver), reads only the panel and its <table>s. Children can style themselves with :global([data-rotated]).
  • Lists: useCapToRows / batched caps show exactly the top 15 and scroll.
  • Speed: RevealOnScroll builds a section only within ~1.5 screens on phones; Records renders 20 rows per list first.
  • Layout helpers: .pair-row (side by side → stacked), 24px bottom padding on phones (desktop keeps a 1000px reading buffer).
Gotchas learned the hard way
  • getBoundingClientRect() returns the transformed box — inside a rotated panel use layout sizes (useElementSize reads borderBoxSize).
  • CSS Modules scope every class, even in compound selectors — toggle with styles.x, never a string.
  • Never hardcode root-relative asset paths; use import.meta.env.BASE_URL.
  • CI uses npm ci — keep exactly one package-lock.json.
  • Don't read layout in a loop after writing styles — batch writes, then reads.
